# פרוטוקול השירות המקומי — גרסת API 1

החוזה בין התוסף (`plugin/`) לבין השירות המקומי (`helper/`). התוסף פונה לשירות דרך `network.fetchStream` של אוצריא, ואין ערוץ אחר.

## 1. ערוץ

- **כתובת:** `http://127.0.0.1:<port>`, כש-`port` הוא הפנוי הראשון בטווח **39700–39709**.
  - 127.0.0.1 משותף לכל משתמשי Windows שמחוברים למחשב.
  - כל משתמש מקבל שירות משלו על פורט אחר, וכל שירות מסרב לבקשות של משתמש אחר (§2).
  - התוסף סורק את הטווח לפי הסדר, ומתחבר לפורט הראשון שעונה לו `"service": "otzaria-responsa"`. את הפורט שעבד הוא מנסה ראשון בפעם הבאה.
- **תבנית:** בקשות ותשובות ב-JSON עם קידוד UTF-8. פעולה ארוכה (בנייה) מחזירה NDJSON: שורת JSON אחת לכל אירוע.
- **בינארי:** אין. `fetchStream` מפענח כל תשובה כטקסט UTF-8, ולכן קובץ בינארי (למשל סמל) עובר ב-base64 בתוך JSON.
- **זמן קצוב:** `fetchStream` נחתך אחרי 120 שניות לכל היותר. לכן:
  - הזרמה ארוכה שולחת `heartbeat` כל 10 שניות;
  - בנייה **אינה** קשורה לחיבור: ניתוק אינו מבטל אותה, וחיבור ב-`attach` מצטרף אליה (§4);
  - פתיחת ספר מוגבלת ל-115 שניות בסך הכול: עד 40 להפעלת בר אילן, ועוד עד 75 לפתיחה עצמה. כך גם חיפוש טקסט (`/text/search`).

## 2. אבטחה

השירות פתוח רק לאוצריא של אותו משתמש. הכללים נאכפים בכל בקשה, **לפני** הניתוב:

| כלל | למה |
|---|---|
| האזנה ל-`127.0.0.1` בלבד | אין גישה מהרשת |
| `Host` יחיד, `127.0.0.1:<port>` או `localhost:<port>`, אחרת 403 | מונע DNS rebinding |
| בקשה עם `Origin`, `Sec-Fetch-Site` או `Sec-Fetch-Mode` נדחית ב-403, גם כשהכותרת מופיעה כמה פעמים | הדפדפן תמיד שולח אותן, ואוצריא (לקוח Dart) אינה שולחת |
| `POST` מחייב `Content-Type: application/json`, אחרת 415 | טופס HTML אינו יכול לשלוח JSON בלי preflight |
| גוף עד 64KB, אחרת 413 | — |
| תהליך הלקוח חייב להיות באותו session של Windows, אחרת 403 `otherSession` | משתמש אחר במחשב היה פותח ספרים על המסך של המשתמש הזה |
| אין כותרות CORS לעולם, ו-`OPTIONS`/`HEAD` מחזירים 405 | — |

**איך נקבע ה-session:**
- **הזיהוי:** הבעלים של החיבור נקבע מטבלת ה-TCP של Windows (`GetExtendedTcpTable`), ומשם `ProcessIdToSessionId`.
- **כשאי אפשר לזהות:** הבקשה **לא** נחסמת. עדיף שירות שעובד על פני דחייה של המשתמש עצמו.

**בזכות כל זה:** המשתמש לא צריך token, צימוד (pairing) או שום הגדרה.

## 3. שגיאות

- **צורה:** כל כשל מוחזר עם סטטוס HTTP וגוף `{"error": {"code", "message", "details"?}}`.
- **`message`:** בעברית, מוכנה להצגה למשתמש, ואומרת מה לעשות.
- **`code`:** קובע את ההתנהגות. אסור להסיק שום דבר מתוכן ה-`message`.

| code | HTTP | מתי |
|---|---|---|
| `notInstalled` | 409 | לא נמצאה התקנה של בר אילן |
| `notRunning` | 409 | בר אילן לא פעיל, ולא הצליח לעלות בזמן |
| `elevated` | 409 | בבנייה: בר אילן רץ כמנהל מערכת והשירות לא |
| `notResponding` | 504 | בר אילן לא עונה |
| `dialogNotFound` | 502 | חלון "עיון" לא נמצא, או שהתוצאות בו לא התנקו. בחיפוש: חלון החיפוש של בר אילן לא נפתח. בבנייה: גם כשהרשימה לא נמצאה בחלון |
| `referenceNotFound` | 404 | אף הפניה לא נפתחה |
| `wrongBook` | 409 | נפתח ספר אחר, והוא נסגר |
| `windowLimit` | 409 | הגעה לתקרת החלונות של בר אילן (כ-22) |
| `busy` | 409 | פתיחה או חיפוש אחרים רצים, או בנייה רצה. בנייה, פתיחה וחיפוש אינם רצים יחד |
| `cancelled` | 409 | הפעולה בוטלה |
| `catalogMissing` | 404 | רשימת הספרים עוד לא נקראה |
| `catalogUnreadable` | 500 | הקובץ קיים אבל לא נקרא, למשל פגום |
| `unknownBook` | 404 | המפתח לא קיים ברשימה |
| `notFound` | 404 | נתיב לא מוכר, או סמל שלא נמצא |
| `badRequest` | 400 | פרמטרים שגויים, או JSON לא תקין. בחיפוש: אין בטקסט אף מילה בעברית |
| `forbidden` | 403 | הפרת כלל אבטחה (§2) |
| `otherSession` | 403 | הבקשה הגיעה ממשתמש Windows אחר |
| `methodNotAllowed` | 405 | שיטה שגויה לנתיב |
| `tooLarge` | 413 | גוף מעל 64KB |
| `unsupportedMediaType` | 415 | `POST` בלי JSON |
| `internal` | 500 | כשל לא צפוי. ה-`message` כולל את הסיבה |

## 4. נקודות קצה

### `GET /health`
מהיר, ואינו נוגע בבר אילן.

```json
{ "ok": true, "service": "otzaria-responsa", "apiVersion": 1,
  "serverVersion": "0.2.0", "capabilities": ["catalog", "open", "icon", "searchText", "export"],
  "sessionId": 1 }
```

**`capabilities`:** מאפשר לתוסף ישן לעבוד מול שירות חדש, ולהפך. יכולת שלא הוצהרה אינה נקראת.

**`apiVersion` שונה מזה של התוסף:**
- **אם הוא נמוך יותר,** התוסף מציג "צריך לעדכן את השירות".
- **אם הוא גבוה יותר,** התוסף מציג "צריך לעדכן את התוסף".

### `GET /status`
מצב ההתקנה, המופע, הקטלוג והבנייה. אינו מפעיל את בר אילן.

```json
{
  "installed": true, "running": true, "version": 25,
  "confidence": "verified", "installPath": "C:\\ResponsaCD25",
  "catalog": { "exists": true, "bookCount": 8402, "schemaVersion": 6,
               "outdated": false, "builtAt": "2026-09-28T19:13:04",
               "sourceVersion": 25, "matchesInstallation": true },
  "build": { "state": "idle" }
}
```

- **`running`:** יש מופע שאפשר לעבוד מולו. מופע "חונה" מחוץ למסך לא נחשב.
- **`confidence`:** אחד מ-`verified`, `structural`, `unknown`.
- **`matchesInstallation`:** `false` כשהרשימה נקראה מהתקנה אחרת.
- **`build.state`** הוא אחד מאלה:
  - `idle`;
  - `running`: עם `startedAt` ושדות ההתקדמות של אירוע `progress`;
  - `failed`: עם `error`, בצורת השגיאה ב-§3.

### `POST /catalog/build` → NDJSON

**גוף:** `{"mode": "start"}` (ברירת מחדל) או `{"mode": "attach"}`. כל ערך אחר מחזיר `badRequest`.

- **`start`:** מתחיל בנייה, או מצטרף לבנייה שרצה. אם פתיחת ספר או חיפוש רצים, מחזיר `busy`.
- **`attach`:** **רק מצטרף.** אם אין בנייה רצה, נשלחת שורה אחת והזרם נסגר: אירוע הסיום האחרון (`done` או `error`), או `{"type":"idle"}` אם לא הייתה בנייה מאז שהשירות עלה.
  - **למה:** התוסף מתחבר מחדש תמיד ב-`attach`, אחרי חסם הזמן או בחזרה ללשונית. כך הוא לעולם לא מתחיל בנייה שאיש לא ביקש.
- **ניתוק:** אינו עוצר את הבנייה.

```
{"type":"start"}
{"type":"progress","stage":"scanning","scanned":412000,"expected":1251889,"sectionsDone":7,"sectionsTotal":20}
{"type":"heartbeat"}
{"type":"progress","stage":"classifying","scanned":1251889,"sectionsDone":0,"sectionsTotal":0}
{"type":"done","books":8402,"scanned":1251889}
```

- **כשל:** שורה `{"type":"error","code":"…","message":"…"}`, ואחריה הזרם נסגר.
- **`stage`:** אחד מ-`starting`, `scanning`, `classifying`.
- **`expected`:** מספר הצמתים מהבנייה הקודמת. בבנייה ראשונה הוא נלקח מטבלת המהדורות המוכרות (25 ו-29). במהדורה אחרת הוא חסר, ויש רק `sectionsDone`/`sectionsTotal`.

### `POST /catalog/cancel`
`{}` → `{"ok": true, "wasRunning": true}`

ביטול שמגיע לפני שהמנוע התחיל לרוץ עוצר את הבנייה גם הוא.

### `POST /catalog/search`
חיפוש בשם הספר, בשם המחבר ובנתיב בעץ. המחבר מופיע לעתים רק בנתיב (`שו"ת > מהרש"א > …`).

```json
{ "q": "מהרש\"א", "offset": 0, "limit": 50 }
```
```json
{ "total": 78, "results": [ { "key": "3232", "title": "…", "author": "…",
  "pubPlace": "…", "pubDate": "…", "edition": "…", "topics": "…", "contextPath": "…/…",
  "otzariaCategory": "תלמוד בבלי/אחרונים" } ] }
```

**אובייקט ספר** (גם ב-`/catalog/books`):

| שדה | תוכן |
|---|---|
| `key` | מזהה הספר ברשימה. תמיד |
| `title` | שם הספר. תמיד |
| `author` | המחבר |
| `pubPlace`, `pubDate` | מקום ושנת ההדפסה, כפי שנקראו מהמהדורה |
| `edition` | שורת המהדורה המלאה מהביבליוגרפיה של בר אילן (קובץ העזרה, CHM), למשל `בני ברק תש"מ, ד"צ`. ממנה נקראו `pubPlace` ו-`pubDate` |
| `topics` | נושאים |
| `contextPath` | הנתיב בעץ של בר אילן, בלי הספר עצמו, `/` בין הרמות. תמיד |
| `otzariaCategory` | הקטגוריה המקבילה בעץ של אוצריא, כשיש שיוך |

- **`edition`:** שדה נוסף, ולכן לא שובר (§7). הוא נקרא מעמודה שכבר הייתה בקטלוג, ואינו מחייב בנייה מחדש.
- **נרמול:** ההשוואה ב-`ResponsaHebrew.spellingKey`. לכן אין השפעה לניקוד, לגרשיים, לכתיב מלא או חסר ולסופיות.
- **דירוג:** כותרת זהה, אחריה כותרת שמתחילה בשאילתה, כל המילים בכותרת, בכותרת ובמחבר, ולבסוף בנתיב.
- **מגבלות:** `q` עד 500 תווים, `offset` ≥ 0, `limit` בין 1 ל-200. שדה ריק לא מופיע.
- **שימוש בתוסף:** כל השדות מוצגים ב"פרטי הספר". `edition` מוצג רק כשיש בו יותר מ-`pubPlace` ו-`pubDate`.

### `POST /catalog/books`
`{"keys": ["3232", "7"]}` → `{"results": [ … ]}`, בסדר שהתבקש. מפתח שאינו קיים מושמט. עד 200 מפתחות. לשימוש עתידי (דפדוף לפי מזהים, היסטוריה).

### `GET /catalog/export`

כל הרשימה בבקשה אחת, כדי שהתוסף יעביר אותה לחיפוש הספרייה של אוצריא (`library.setProviderBooks`) בלי אלפי בקשות. יכולת: `export`.

```json
{ "builtAt": "2026-09-29T10:00:00", "books": [["7008", "אבני נזר", "רבי אברהם בורנשטיין", "שו\"ת"], ...] }
```

- **שורה:** `[key, title, author | null, contextPath]`. `contextPath` כמו ב-`/catalog/search` (`/` בין הרמות, בלי הספר עצמו).
- **גודל:** כ-950KB ל-8,402 ספרים (CD25), פחות משנייה.
- **שגיאות:** כמו `/catalog/search` (`catalogMissing`, `catalogUnreadable`, `busy` ברגע ההחלפה).

### `POST /book/open`
```json
{ "key": "3232" }
```
- **הצלחה:** `{"ok": true, "window": "…", "usedRef": "…", "broughtToFront": true}`.
- **כשל:** אחד מקודי השגיאה בסעיף 3. ב-`details` מופיעות `triedRefs`.
- **איך נפתח ספר:**
  - השירות מביא את ההפניות מהקטלוג בעצמו, והתוסף לא שולח הפניה;
  - אם בר אילן סגור, השירות מפעיל אותו;
  - השירות מנסה להביא את החלון לחזית.
- **`broughtToFront: false`:** Windows סירב להביא את החלון לחזית. הספר נפתח, והתוסף מסביר שהחלון בשורת המשימות.
- **מתי נדחית:** פתיחה נדחית ב-`busy` אם פתיחה אחרת, חיפוש או בנייה רצים.

### `POST /text/search`
יכולת `searchText`. מריץ חיפוש טקסט מלא בבר אילן, כאילו המשתמש הקליד את הטקסט בחלון החיפוש שלו. התוצאות **נשארות בממשק של בר אילן**, והשירות אינו מעתיק מהן דבר. אינו תלוי ברשימת הספרים.

```json
{ "q": "הטקסט שנבחר באוצריא" }
```
```json
{ "ok": true, "outcome": "found", "count": 2543, "query": "הטקסט שנבחר באוצריא",
  "truncated": false, "broughtToFront": true }
```

- **`q`:** הטקסט כפי שנבחר. **מעל 10,000 תווים הוא נחתך, ואינו נדחה**: רק תחילתו נשלחת לבר אילן בכל מקרה, ולקוח ישן אינו מקצר את הבחירה בעצמו. התוסף הנוכחי שולח עד 2,000 תווים. השירות מנקה אותו בעצמו (`ResponsaQuery`):
  - נשארות רק מילים עבריות, מופרדות ברווח;
  - ניקוד, טעמים, פיסוק, ספרות ולטינית נמחקים. מקף מפריד בין מילים;
  - תווי החיפוש המתקדם של בר אילן (`# * ! + $ - < > { } % ^ ~ ?`) נמחקים, כדי שלא יפעלו כאופרטורים;
  - גרשיים נשמרים בתוך מילה (`רמב"ם`), וגרש גם בסופה (`ר'`). `״`, `׳` ומירכאות טיפוגרפיות מנורמלים ל-`"` ול-`'`;
  - עד 10 מילים ו-120 תווים.
- **`query`:** מה שנשלח לבר אילן בפועל. **`truncated: true`:** הבחירה קוצרה לעשר מילים או ל-120 תווים, והתוסף יכול לומר זאת.
- **`outcome`:** מה בר אילן השיב. בכל המקרים החלון שלו **נשאר פתוח** לפני המשתמש:

| `outcome` | מה על המסך בבר אילן | שדות |
|---|---|---|
| `found` | חלון התוצאות, ומעליו חלון הסיכום (`2543 תוצאות`) | `count` |
| `asked` | "לא נמצאה כל תוצאה! … האם ברצונך לחפש בכל המאגרים?". המשתמש עונה בבר אילן | `message` |
| `refused` | הודעה, למשל "נמצאו מעל 32000 תוצאות. נא לפשט את החיפוש…" | `message` |

- **`message`:** הטקסט של בר אילן, ברווחים רגילים. אם לא נקרא, השירות שולח הסבר משלו.
- **`count`:** רק ב-`found`, כפי שנקרא מכותרת חלון הסיכום או חלון התוצאות.
- **אם בר אילן סגור או ממוזער:** השירות מפעיל אותו (לפי `autoStart`, כמו בפתיחה) או משחזר אותו, ומביא אותו לחזית. `broughtToFront` כמו בפתיחה.
- **כשל:** `badRequest` (אין מילה עברית), `busy`, `notInstalled`, `notRunning`, `dialogNotFound` (חלון החיפוש לא נפתח), `windowLimit`, `notResponding` (בר אילן לא השיב בזמן).
- **מתי נדחה:** ב-`busy`, אם חיפוש אחר, פתיחה או בנייה רצים.

### `GET /icon`
`{"png": "<base64>"}`, או 404 `notFound`. הסמל נחלץ מ-`RESPONSA.exe` שבמחשב, כי הוא סימן מסחרי ולכן לא נארז. לשימוש עתידי.

## 5. מיקומים

| מה | איפה |
|---|---|
| השירות | `%LOCALAPPDATA%\Programs\OtzariaResponsa\` |
| קטלוג, סמל ויומן | `%LOCALAPPDATA%\OtzariaResponsa\` |
| הפעלה | בכניסה למשתמש (HKCU\Run), **לא** שירות Windows |

**למה לא שירות Windows:** שירות רץ ב-Session 0, ומשם הוא לא רואה את חלונות בר אילן בסשן של המשתמש.

**שרידות:** הקטלוג מחוץ לתיקיית הספרייה של אוצריא, ולכן התקנה מלאה של אוצריא והעברת ספרייה לא מוחקות אותו.

## 6. מופע יחיד וקודי יציאה

**הנעילה היא הפורט.** השירות עובר על הטווח לפי הסדר. לכל פורט:
- **פנוי:** מאזינים לו, וזהו.
- **תפוס בידי השירות של אותו משתמש** (`/health` מחזיר 200 עם `service` שלנו): יציאה בקוד **3**, "כבר רץ".
- **תפוס בידי משתמש אחר** (`otherSession`) **או תוכנה אחרת:** ממשיכים לפורט הבא.
- **כל הטווח תפוס:** יציאה בקוד **4**, והיומן מפרט מה נמצא בכל פורט.

| קוד | משמעות |
|---|---|
| 0 | יציאה רגילה |
| 2 | ארגומנטים שגויים |
| 3 | השירות של המשתמש הזה כבר רץ |
| 4 | אין פורט פנוי בטווח |

**`--port=<n>`:** מבטל את החיפוש בטווח. לפיתוח בלבד.

## 7. גרסאות

- **`apiVersion`:** עולה רק בשבירת תאימות.
- **תוספת לא שוברת:** שדה חדש או נקודת קצה חדשה נכנסים כ-`capability`, בלי להעלות את `apiVersion`.
- **שדות לא מוכרים:** התוסף מתעלם משדות שאינו מכיר.
